# 🚨 EXECUTION RULES

You are the implementation agent.

Do not merely produce another architecture document.

You must inspect the existing YMONEY repository and incrementally implement this plan.

## Mandatory rules

1. 🔍 Inspect the existing code before changing architecture.
2. ♻️ Preserve every working feature unless replacing it with a demonstrably superior implementation.
3. 🚫 Do not rebuild working systems unnecessarily.
4. 🧱 Use adapters/interfaces around every major OSS dependency.
5. 🔌 OSS projects are components, not YMONEY's architecture.
6. 🚫 Never blindly copy an entire external repository into YMONEY.
7. 📌 Pin production dependencies to known versions/commits.
8. ⚖️ Inspect the LICENSE of every repository and every downloaded model weight before integration.
9. 🚫 Do not integrate GPL/AGPL or non-commercial components into the commercial product without explicit license approval.
10. 🧾 Code license and model-weight license must be checked independently.
11. 🔐 Never commit API keys, credentials, cookies, OAuth tokens or `.env` secrets.
12. 🧪 Mocks are permitted in tests only. Production paths must use real implementations or explicitly report that a provider is unavailable.
13. 🛡 Destructive, financial, publishing and account-level operations must remain deterministic and permission-controlled.
14. 🤖 AI/Jev judgments must never replace authentication, permissions, budgets or safety invariants.
15. ✅ No phase can be marked complete merely because code was written.
16. ✅ Tests/build/type-check/lint/E2E evidence is required.
17. 📝 Maintain architecture and OSS integration documentation as implementation proceeds.
18. 🔄 Every new subsystem must have an interface allowing replacement later.
19. 📊 Instrument cost, latency, failures and provider usage.
20. 🧩 Prefer extending existing YMONEY components over creating duplicate systems.
